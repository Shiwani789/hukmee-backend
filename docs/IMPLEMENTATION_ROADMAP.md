# HUKMEE implementation roadmap

The approved architecture remains Node.js/Express, TypeScript, PostgreSQL and Prisma. A separate approved Master PRD/SOW is unavailable in the repository. A Postman collection for all mounted write operations is now maintained at `docs/HUKMEE.postman_collection.json`. Traceability is limited to the user-pasted S1/S2 context, repository requirements and current models. Current executable source was re-audited on 2026-10-16. The active app builds and lints; dormant legacy modules remain excluded because they do not compile against the current schema.

## Current verification status (2026-10-16)

The pasted context is **not fully implemented**; no separate approved SOW is available to certify scope. The canonical app mounts auth, catalog, devices, bookings, inventory, user profile and addresses. Payment, KYC/vendor, notifications, CMS and reviews legacy routes are not mounted; legacy source is excluded from TypeScript and ESLint because it references obsolete models/middleware/dependencies. Do not treat those files as working APIs. The schema has `TECHNICIAN`, not `VENDOR`; use the existing technician account as the vendor/technician persona and do not create another account flow. Legacy KYC code has distinct WORKER and DELIVERY_PARTNER branches, but neither is an active role/model here. A dedicated test DB URL is not configured. The active-source build/lint do not validate excluded legacy code.

Follow-up verification (2026-10-16): full Jest run passes 14 suites / 48 tests; 1 integration suite/test is skipped. Mocked admin catalogue, technician profile/status, inspection/estimate, device/catalogue and existing service/API tests pass. Active-source build, lint, Prisma validation with a non-contacted placeholder URL and changed-file formatting checks pass. No DB integration, migration or provider integration was run. Postman contains the existing 21 write operations, 2 technician reads, and 29 admin catalogue request examples.

## Working rules

- Preserve existing Prisma models and migrations unless a demonstrated approved requirement needs a change.
- Do not infer fees, pricing, timeouts, slot duration, commission, or cancellation policy from examples or schema fields.
- Treat unresolved entries in [open decisions](OPEN_DECISIONS.md) as unresolved policy, not defaults.
- `npm run test:integration` is opt-in and requires a dedicated migrated database named with `_test`; it does not create, reset, or migrate a database.
